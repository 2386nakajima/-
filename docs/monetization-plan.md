# 収益化設計 — WakeUpQR

**方針:** 起床という「絶対に失敗できない瞬間」を扱うアプリなので、信頼を損なう手段（広告・過度なペイウォール）は使わない。**フリーミアム＋低価格買い切り**で、レビュー資産と口コミを最優先する。

---

## 1. 収益モデルの比較と結論

| モデル | 長所 | 短所 | 採否 |
| --- | --- | --- | --- |
| 買い切り（Pro解放） | サブスク疲れ層に刺さる。競合Alarmyがサブスク主体なので差別化になる | LTVに上限 | **採用（主軸）** |
| サブスク | 継続収益 | 目覚ましは「維持費を払う」納得感が弱い。解約時にアラームが弱体化するのはUX的に危険 | 見送り（統計・クラウド同期など継続コストのある機能を将来追加したら再検討） |
| 広告 | 無料ユーザーからも収益 | 起床画面に広告はUX破壊。誤タップでアラーム解除の信頼性を損なう | 不採用 |
| 投げ銭・応援課金 | 実装が軽い | 収益として計算できない | 補助的に検討可 |

## 2. 無料/Proの線引き

**原則: 「確実に起きる」というコア価値は無料で完全に提供する。** 無料版が信頼できないアプリに課金は発生しない。課金は「ヘビーユーザーの利便性」に対して行う。

| 機能 | 無料 | Pro |
| --- | --- | --- |
| QRアラーム | 1件 | 無制限 |
| 登録QRコード | 1枚 | 複数（部屋ごと等） |
| アラーム音・音量フェード | 基本 | 全種類＋カスタム |
| 厳格モード（スヌーズ禁止・音量固定） | — | ✔ |
| 起床履歴・統計 | — | ✔ |
| バックアップ/機種変更引き継ぎ | — | ✔ |

## 3. 価格

- **Pro買い切り: ¥600**（仮説）
  - 根拠: 「失敗しない朝」への支払いとしてコーヒー1杯級の心理的ハードル。競合サブスク（年額数千円）に対する「一度きり」の明確な優位。
  - ローンチ記念で¥480などの導入価格 → レビューが溜まったら定価に戻すテストを行う。
- 価格は仮説。**転換率×価格の総額を見て改定する**（値付けは後から上げにくいので、迷ったら安すぎない側に倒す）。

## 4. 実装設計

### App Store（アプリ内課金）

- **StoreKit 2 + RevenueCat** を採用。
  - RevenueCatは月間トラッキング収益$2,500まで無料。レシート検証・復元・返金処理を自前実装しなくて済む。
  - Expoでは `react-native-purchases`（RevenueCat公式）を development build で組み込む（Expo Goでは動作しないため、Phase 4はEASビルドが前提）。
- 商品構成: 非消耗型（Non-Consumable）1つ = `wakeupqr_pro`。
- 「購入の復元」ボタンは審査必須要件なので設定画面に必ず置く。

### Web直販（将来オプション）

- LPからのWeb直販（Stripe決済＋ライセンスコード）はAppleの手数料30%（小規模事業者プログラム申請で15%）を回避できるが、特商法表記・決済管理の負担が増えるため、**App Store課金が軌道に乗るまで着手しない**。

## 5. ファネルとKPI

```
LP訪問 → 事前登録 → DL → 起床成功体験 → Pro購入 → レビュー投稿
```

| 段階 | 指標 | 初期目標 |
| --- | --- | --- |
| LP | 訪問→事前登録率 | 5% |
| ストア | ページ閲覧→DL率 | 30% |
| アプリ | DL→初回アラーム設定率 | 60% |
| 課金 | 無料→Pro転換率 | 2〜5% |
| 口コミ | レビュー平均 | ★4.5以上 |

- 計測は初期はストア標準（App Store Connect）＋RevenueCatダッシュボードで足りる。外部アナリティクスSDKはプライバシー訴求と矛盾するため慎重に。
